# News slides

**Status:** Verified · **Owner:** Repository maintainers · **Last verified:** 2026-10-21

News slides are a standalone, animated HTML presentation prepared from an index alone or a saved daily report and its matching index. The report mode is described first; the index-only path below skips report writing. Each selected story occupies one navigable slide with source, summary, available images, captions, and model-written narration. The candidate pool is the whole saved report: all selected events and briefs, regardless of publication date; slides do not add items directly from the index. Duplicate original stories are merged with all source references retained, then ranked by model-authored importance. The default is the most important 30 stories; `slides prepare --max-news N` sets another positive limit, and `finalize-edition --slides-max-news N` configures the default edition workflow. There is no per-source quota. A new edition defaults to 30; resuming an existing run without an explicit limit preserves its saved choice, while an explicit change prepares a new plan. Unknown publication dates stay unknown and are not replaced with discovery, collection, or index-update time. Missing images do not exclude stories. This projection does not change the report. When a deck exists, the report HTML embeds it in the **Report visual stream and video** section in place of the on-screen executive summary and keeps an **Open presentation** link for opening the deck separately. Printing hides the embedded presentation and restores the summary. The daily report's JSON and Markdown remain unchanged and authoritative; later HTML rebuilds retain the presentation while its projection exists.

The visual reference is [Frontend Design example site 02](https://mimo.xiaomi.com/mimo-v2-6/assets/frontend/site-02/): warm off-white (`#f3f4ef`), deep green ink (`#1c2422`), restrained terracotta accents, oversized serif headlines, asymmetrical editorial columns, fine rules and side numbering. News images retain their original proportions, and transitions respect reduced-motion preferences. The template is local and deterministic, so styling adds no model calls or generation cost.

Online page requests share one HTTPX connection pool. A per-domain round-robin scheduler fills newly free global worker slots while respecting global and per-domain limits; image downloads also use bounded concurrency.

Image downloads, image-refresh page requests, and public DNS-over-HTTPS lookups follow the process environment's `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, and `NO_PROXY` settings. When local DNS fails or returns a proxy fake IP, public DNS must confirm a public destination before downloading. Private destinations remain blocked, including redirect targets. Report `media_metrics.candidates` counts news entries with image candidates, not HTTP requests; fallback URLs, cache reuse, and redirects can change the request count.

Story imagery combines cover and article-body candidates from the index with images and original captions extracted from each selected story's public article page during the default online render. For arXiv abstract pages, rendering follows only the explicitly linked HTML full text for the same paper to find supported body images; SVG figures remain unsupported. Explicit `srcset` and URL size/DPR declarations guide selection of higher-resolution candidates; actual resolution depends on what the publisher exposes and downloads successfully. Images inside in-article game, promotion, subscription, or same-page recommendation containers are not treated as article imagery, and candidates that resolve to identical content are shown once. Candidates are deduplicated by image identity; the renderer does not impose a six-image cap. Downloads follow configured media budgets. A failed page fetch or image download leaves the existing indexed candidates available. This refresh only updates slide imagery; it does not change saved body evidence or access status. The gallery provides thumbnails, a larger view, 100% original-size inspection, and a direct link to the original image. Publisher captions remain attached to their images; missing captions stay empty and are never replaced with alt text. The current and next story images load eagerly; images in distant stories stay lazy until needed. Shared local images are encoded once per render.

Use global `--compact` before the subcommand to bound stdout without changing saved artifacts. Start each writing task with only its packet and the absolute CLI invocation. Keep the default 30 stories unless the user requests another limit. The model reviews the initially ranked candidates for current relevance and duplicate coverage; exclude stale or duplicate events when needed so preparation fills from the next eligible stories. After a bounded evidence retry, exclude an unsupported story with `finalize-edition --slides-exclude-event-id EVENT_ID`; standalone `slides prepare` uses `--exclude-event-id EVENT_ID`. Repeat the option for multiple stories. Preparation fills from the next eligible candidates and reuses unchanged accepted narration; complete only pending packets.

## Index-only visual stream

When the user wants only a visual stream, collect an index and have a model select the most important 30 candidates in order. Pass their exact item IDs to preparation using repeated `--item-id`; use `--max-news N` for another requested limit. CLI preparation automatically extracts missing or incomplete bodies for selected stories and reuses available evidence:

```text
signaltrail --data-dir DATA_DIR slides prepare --index INDEX.json --language en --item-id ID1 --item-id ID2
```

No report, brief authoring, or report analysis is required. For an explicit evidence retry, the coordinator runs `extract-content` for selected items and prepares new packets from its returned index; workers do not invent details to meet a length target. The host model selects ordered indexed item IDs by importance; preparation deduplicates original URLs. Without explicit IDs the CLI retains its stable `source_rank` fallback, but the skill workflow supplies model-selected IDs. Positive `--min-importance` is unavailable when the index has no importance scores. Language comes from explicit `--language`, then `config.output.language`. Report mode follows the saved report language and rejects an explicit conflicting language. Model output includes target-language `title`, `summary`, `narration`, `video_tldr`, and `perspectives`; perspectives stay empty without supplied analysis. Follow the packet's mode-specific output schema and instructions. Python attaches sources, publication dates, and images; unknown dates remain unknown. Submit pending packets, check status, then render as below. The result is an independent deck and does not create a report or update report projections.

Use `--reuse-plan OLD_PLAN.json` to reuse accepted stories whose complete writing inputs are unchanged, including across index/report revisions. Changed text, language, or analysis requires fresh writing; image-only changes can reuse writing. Preparation and status expose `reused_count` and `pending_news_count`, and reused stories do not produce pending model packets. Report finalization supplies its previous plan automatically. These savings depend on the available accepted inputs; no fixed time or cost reduction is promised. Actual unmetered costs remain `null`.


## Default daily flow: prepare, write, render

Finalizing a daily report automatically prepares a slide plan and bounded writing packets from
the saved report and matching index. Every default daily edition requires a rendered slide deck, in metered and unmetered runs. “Report saved” means the report artifacts are available; “edition delivery complete” requires all slide batches accepted, rendering finished, the tail exited, and the completion gate passed. A saved report and HTML may be handed off while the rest is pending. The run manifest records them at
`artifacts.slides.plan_path` and `artifacts.slides.packet_paths`; no model call is made during
preparation. Packets are independent: run at most three isolated workers concurrently and fill
each open slot with the next packet in order as soon as a worker finishes. Without isolated workers,
process packets sequentially. Submit each result using the manifest paths. Reuse accepted results
and write a uniquely named draft JSON beside each packet. If finalization used `--defer-tail`, run
the manifest's exact `tail.command`; overlap it with slide writing only when the host supports
concurrent processes. Wait for it to exit before rendering because both operations can update report
projections. If preparation fails, the report remains
saved and `artifacts.slides.error` records the reason. To register a failed or missing preparation
in the run manifest, retry `signaltrail --data-dir DATA_DIR finalize-edition --run RUN.json --report
SAVED_REPORT.json --defer-tail`; standalone `slides prepare` remains available for independent use.
Then check `slides status --plan PLAN.json`, render only after all batches are accepted and tail exits,
and run `signaltrail --data-dir DATA_DIR edition-status --run RUN.json --require-complete`; require
`delivery_complete: true`, empty `pending_steps`, and `slides.status: rendered`. This dynamic command
is authoritative; run status and saved slide snapshots may precede rendering. Disclose every pending
step if the gate is false.

## Prepare, write, render

Collection also reads an image's explicit full-size link when present. Known CDN size variants are merged without inventing URLs, and a higher-resolution remote image never inherits a thumbnail's local cache file. Captions stay within the image container; quotation attributions elsewhere in the article are excluded. Opening a larger image from the embedded deck expands its viewport above the report toolbar, then restores the container on close.

Prepare a slide plan from a saved report and its matching index:

```text
signaltrail slides prepare --report REPORT.json --index INDEX.json
```

By default, candidates are the entire saved report's selected events and briefs. SignalTrail merges duplicate original stories, keeps all source references, ranks by model-authored importance, and prepares the most important 30. Use `slides prepare --max-news N` for another positive limit, or `finalize-edition --slides-max-news N` for the edition workflow. The limit is issue-wide; it does not reserve a place for each source. When resuming, omission of `--slides-max-news` reuses the saved limit; an explicit change prepares a new plan. Items with unknown or older publication dates remain eligible because the report is the scope. Unknown dates remain unknown and are never filled from discovery or collection timestamps. Missing images do not exclude a story. Each packet assigns a bounded group of stories to one writing call; the default batch size is five. The packet carries the style instructions, output schema, allowed analysis perspectives, and assigned report evidence.

Read only `packet.payload.model_input` to write the batch; its schema is at `payload.model_input.output_schema` and cost reserve is separate at `payload.budget`. Submit the resulting JSON with `signaltrail slides submit --packet PACKET.json --input DRAFT.json`. In report mode, emit every assigned event exactly once as `{event_id, narration, video_tldr, perspectives}`. `perspectives` may be empty and may contain only relevant `geopolitics`, `markets`, or `ai_technology` domains present in that event's analysis. Do not repeat titles, summaries, sources, image URLs, or captions in the model output; the renderer attaches these program fields. A successful submission is reused. Invalid drafts do not trigger an automatic repair. Keep each worker on one packet and do not exceed three concurrent packets; as each worker finishes, assign the next packet in order.

The packet contains a copy of the [narration style](../templates/news-slide-style/SKILL.md), so a worker can follow its voice without loading extra editorial material. Chinese narration is validated at 200–350 non-whitespace characters, including punctuation; English narration has no equivalent length check. This structural validation does not independently verify facts. Collection should cover available Chinese- and English-language sources and check overall language coverage, without filtering sources to match output language. The user's explicit language choice takes priority, followed by saved preference or the current run, then `zh-CN` by default. The coordinator sets the same target language for the report and packet; writers follow `payload.model_input.language` without choosing again. Keep original titles and URLs for traceability. Do not require bilingual evidence for every story or count republications as independent support. Check names, figures, roles, tense, and qualifiers across languages; resolve material conflicts with evidence or leave them unknown.

Fact checks start during collection and selection: confirm the source's actors and roles, tense, dates, and key figures, and seek primary or independent evidence when an error could materially mislead. Keep verification notes backstage. While drafting, review every sentence and any assertion introduced by an analogy against the bounded evidence; preserve qualifiers such as “alleged,” “plans,” or “claims.” If support is missing, pause the draft; do not edit a frozen packet. The coordinator resolves the gap and issues a new packet version before writing resumes, or the unsupported claim is omitted. Read the [budget and packet reference](../references/news-slides.md) when changing batch size or token gates.

State facts, mechanisms, and conclusions directly. Avoid repeatedly following a claim with “does not mean,” “does not prove,” or similar defensive phrasing. Put material unresolved risks in one dedicated limitations paragraph, and state essential factual qualifiers once, naturally. Write in a vivid, spoken news-comedy voice by default: first pick one compelling tension or observation backstage, then let the audience hear the finished narration, not the fact-check process, a how-to, or a list of caveats. State a conclusion-relevant qualifier such as “some models” or “can be disabled” once, naturally. Use a fitting analogy to explain the mechanism; let sentence length and pauses create rhythm. End on an evidence-backed point or image, not a list of facts. Humor is optional; use a serious tone when the subject calls for it. Do not joke about victims, uncertainty, or missing evidence; do not invent quotations or inner thoughts. Avoid padding with repeated phrases such as “materials are limited,” “geopolitical analysis,” or “watch what happens next.”

Use the exact plan and packet paths recorded in `artifacts.slides.plan_path` and `artifacts.slides.packet_paths[]`; do not infer them from revision names. Save each draft beside its packet as `batch-N-draft.json`, using that packet’s batch number. Run these commands with the same data root. Render only after all planned batches have been submitted and the tail has exited:

```text
signaltrail --data-dir DATA_DIR slides submit --packet PACKET.json --input DRAFT.json
signaltrail --data-dir DATA_DIR slides status --plan PLAN.json
signaltrail --data-dir DATA_DIR slides render --plan PLAN.json
signaltrail --data-dir DATA_DIR edition-status --run RUN.json --require-complete
```

Append `--check-only` to submission to report all draft errors without saving a result. For several ready drafts, use `slides submit --plan PLAN.json --draft-dir DRAFT_DIR --check-only`, then repeat without `--check-only` to submit valid batches together. Drafts are named `batch-N-draft.json`; the earlier `slides-draft-N.json` name is also accepted. The result lists `accepted`, `pending`, `invalid`, `expected_paths`, and per-batch errors. Valid drafts awaiting submission have status `ready_to_submit`; only accepted batches count as complete. Unsupported number expressions in spoken text are caught before video export.

Rendering produces a navigable HTML deck, a structured deck JSON, and Markdown. Story titles, summaries, and source references come from the report; the index supplies source names, publication times, and cover plus article-body image candidates. By default, render reads the selected stories' public article pages to supplement image candidates and publisher captions. It follows explicit `srcset` entries and declared URL width/DPR when choosing among variants, then caches successful downloads within configured media budgets. Page or image failures preserve the existing candidates. This image refresh does not alter stored article text, its evidence, or its access status, and makes no model call. Use `--offline` to rebuild from the existing deck and image files without fetching pages or downloading images, for layout-only changes. Candidates are deduplicated by image identity; resolution is limited by publisher-provided variants and download success, and there is no fixed per-story image limit. The gallery supports thumbnail selection, a larger view, 100% original-size inspection, and opening the original image URL. If any writing batch is pending or missing, render stops; it does not silently omit assigned stories. Status reports completed and pending batches. HTML styling and transitions are deterministic.

CLI preparation and report finalization extract missing or incomplete bodies for selected sources before freezing the writing packets, preserving actual access failures and extraction gaps. Automatic body extraction covers configured report and monitor sources; unconfigured sources retain their existing evidence. Both report and index modes include the complete available text of selected sources in `payload.model_input.news[].evidence[].body`, alongside `content_status`, `content_quality`, and `content_completion`. Writers read each source body before choosing an angle and explaining the event, mechanism, and details. Bodies are read as complete UTF-8 text without character truncation. Split batches around the default 64,000-token input target; one longer story automatically raises the allowance. Explicit `--max-input-tokens` is a hard limit: an oversized story is rejected with the enriched index path, which can be reused after adjusting the allowance. Preserve the actual status and gaps of incomplete extraction, and collect major unresolved risks in a dedicated limitations paragraph. Online rendering separately refreshes imagery; offline rendering uses the existing deck and local images.

## Batch cost gates

Use `--max-news` to set the issue-wide story count, and `--batch-size`, `--max-input-tokens`, and `--max-output-tokens` for per-batch limits. Defaults are 30 stories, five stories per batch, a 64,000-token estimated input target that expands for one longer story, and 4,000 estimated output tokens. Explicit `--max-input-tokens` sets a hard limit. Report mode reserves 700 estimated output tokens per story; index-only mode reserves about 1,000 because it also writes titles and summaries. Input estimate is serialized UTF-8 bytes divided by two, plus 512 tokens of reserve. These are coarse size gates, not tokenizer counts, dollar quotes, or guarantees of host usage. Actual usage remains unknown (`null`) unless the host exposes it. Selected stories are handled through as many batches as needed.

The host is responsible for making the writing call. SignalTrail prepares bounded packets and accepts results; it does not automatically invoke a model, retry a draft, or incur a separate review call.

## Local narrated video

The model writes a concise `video_tldr` based on the full narration: target 60–100 Chinese characters, with a maximum of 160 characters. Video reads the title and this short script.

```text
signaltrail --data-dir DATA_DIR slides voice-setup --profile PROFILE.json --default
signaltrail --data-dir DATA_DIR slides video-setup
signaltrail --data-dir DATA_DIR slides video --deck DECK.json --output VIDEO.mp4
```

When the deck belongs to a saved report, successful video export adds **Open video** beside **Open presentation** in the **Report visual stream and video** section. The video plays in the same frame, and the reader can switch back to the presentation. The presentation link still opens the deck separately. The report's existing desktop HTML copy is refreshed as well. Later report or slide HTML rebuilds preserve these controls; printing hides the embedded section. Index-only decks remain standalone. The report JSON and Markdown retain their saved revision.

The default engine is native Qwen3-TTS 1.7B Q8. For a new installation, prepare your own 3–10 second reference recording and exact transcript, complete `assets/tts/profile.example.json`, and register the profile as the default voice. Existing locally registered voices and older local bundles remain usable. Setup downloads programs, models, FFmpeg and browser for the detected platform; `slides video` also prepares missing tools and reuses the cache. Users do not install Python TTS or CUDA packages. Initial preparation may use the network; subsequent local synthesis and rendering reuse cached files. Windows ARM64 requires an explicit `--ffmpeg`. The Linux harness supplies browser system libraries and Chinese fonts.

Speech contains the title and `video_tldr` at 1.08× speed. Actual audio duration controls page changes and image rotation. HTML playback starts the current story again when resumed.

Qwen audio synthesizes each page’s title and short script in bounded segments. Complete sentence caches from earlier exports are reused. Numeric ranges, dates, negative values, and identifiers such as CVE numbers receive distinct pronunciation rules; the displayed text stays unchanged. A native frame-limit stop or an invalid WAV fails the page before it is accepted into the audio cache.

Whole-page audio is reused when its text, language, voice, processing settings, and WAV contents match. Export reports `tts_page_cache_hits` for page reuse, `tts_cache_hits` for reused sentence segments, and `tts_segments_generated` for new synthesis calls. Cached manifests retain original synthesis evidence; stage diagnostics measure the current export. For Qwen playback, low-energy intervals longer than one second are shortened when 20 ms windows remain below -45 dBFS. Interior intervals retain 0.7 seconds; beginning and end intervals retain 0.2 seconds, with fades at cuts. Native segments and the joined raw WAV remain unchanged; `silence_removed_seconds` records the removed duration.

Video captures the original slides HTML with its text, images, and column layout preserved. Video capture applies 140% whole-page zoom, enlarging text and images; the slides HTML remains unchanged. The video automatically follows the original page and image order, including existing placeholders and remote images; measured speech duration determines each page’s display time.

Keep the output path stable to reuse `OUTPUT/page-cache/` beside `OUTPUT.mp4`. Each page clip depends on the original HTML, page position, measured duration, and rendering and encoding settings. A matching page without external images can skip browser rendering and encoding; pages with external images are rendered again. Stderr reports progress. The returned `diagnostics_path` records stage results and timings, `timeline_path` records audio/image timing, and page voice manifests retain synthesis inputs and native logs. `pages_rendered`, `page_clips_generated`, and `page_clips_reused` show actual work. Keep the current output and useful evidence, and move superseded output directories to the OS recycle bin when cleaning up.

Runtime sources: [llama.cpp b11981](https://github.com/ggml-org/llama.cpp/releases/tag/b11981), [Qwen3-TTS 1.7B Base GGUF](https://huggingface.co/ggml-org/Qwen3-TTS-12Hz-1.7B-Base-GGUF), [FFmpeg binaries](https://github.com/imageio/imageio-binaries/tree/master/ffmpeg), and [Playwright browsers](https://playwright.dev/python/docs/browsers).


The harness prefers a GPU confirmed by a real synthesis probe and falls back to CPU when unavailable. Use `--device auto|cpu|cuda|vulkan|metal` or `SIGNALTRAIL_TTS_DEVICE`; the default is `auto`. The pinned llama.cpp b11981 release provides CPU, CUDA and Vulkan packages for Windows/Linux x64 and ARM64, and CPU/Metal packages for macOS x64 and ARM64. Preparation selects a released package; the synthesis probe verifies its operation on the current machine. Export records the actual provider, model, device and synthesis time. `--tts-executable` and `--model-dir` can reuse existing tools and models.


### Broadcast delivery

Write `video_tldr` from the full narration; make the title and short script complementary, and audition numbers and proper names in both Chinese and English. Follow the [broadcast reference](../references/news-slides.md#新闻播报). Use the registered Qwen3 reference voice; record the model, language, device, duration and current audition result.


### Portable voice packs

Import a voice with `slides voice-setup --profile PROFILE.json --default`. Reference recordings are copied into `video-runtime/voices/NAME/` under the data root and stored as relative paths, so the directory can be copied to another harness. Choose `slides video --voice NAME` or `--voice PROFILE.json`; omission uses `SIGNALTRAIL_VOICE`, then the registered default. `--reference-id ID` selects another reference explicitly. The registered default remains in use; references are not rotated randomly.

The profile uses `engine: qwen3`, `reference_id` and `references: [{id, audio, text, language}]`, with recording paths relative to the profile. Settings are `seed: 42`, `context: 4096`, `max_frames: 500`, `speed: 1`, `gain_db: 0`, and `peak_limit: 0.794`. A new Qwen page uses punctuation for internal pauses and adds the configured 0.2-second ending pause; legacy sentence-cache assembly retains the 0.45/0.35-second title/sentence pauses. Reference text matches the recording exactly. The upstream deck language controls synthesis; author English with `slides prepare --language en`. The speech normalizer expands numeric expressions, while Qwen pronounces words and names without the legacy engine's forced-spelling mappings.

Programs and models remain cached after setup. Original streams, additional reference candidates and model caches stay in runtime data; the public skill includes a profile example; reference recordings remain local.
