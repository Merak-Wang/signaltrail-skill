# 路线图：新闻讲解

**状态：** 草稿（Draft） · **负责人：** 仓库维护者 · **最后验证：** 2026-09-08

本提案把已完成的报告扩展为有证据的讲解稿，再按需生成音频和视频。这些能力均尚未交付。
本文合并原先重复的产品、架构和执行提案，统一范围与验收要求。[English](../roadmap.md)

## 预期结果

先提供分章节的文字讲解：发生了什么、为何重要、事件之间有什么联系、可信解释之间有何分歧。
每个重要 claim（主张）关联父报告已接纳的证据；beat 是读者可见的一小组相关主张。

独立验证者检查每个发布的 claim 和 beat 是否有支持、归因是否准确、时间是否合适，
以及不确定性和矛盾是否得到处理。关键发现未解决时，讲解稿保持 Draft。
已接收的文字提供语义修订一致的 HTML 和 Markdown。

后续阶段把已验证 beat 转为有序场景计划，选择授权素材，生成语音、实测字幕和新闻讲解视频。
媒体失败不影响已验证文字。公开渠道发布和直播不在本提案范围内。

## 边界

```text
已完成报告 + 索引 → 有界叙事包 → 讲解稿修订
→ 独立验证 → 当前验收回执 → HTML / Markdown
→ 场景计划 + 授权素材 → 语音 / 字幕 / 视频
```

Python 负责 ID、修订、Schema、证据授权、哈希、新鲜度检查及后续阶段准入。
模型只写作或评判收到的数据包，作者和验证者彼此隔离。
下游阶段不能写回父报告、索引或连续状态。

每份语义产物有独立的不可变修订和父级哈希。验收回执绑定讲解稿、验证、父报告/索引与策略版本。
父级、证据指纹、新鲜度判断或策略变化时需要新的当前决定，旧回执保留为历史。
这些绑定仍匹配时，可以复用相同的已完成工作。

媒体场景标识其解释的 beat，并记录每项素材的来源和使用权。
权利未知、未经批准的声音克隆、虚构引言和无法核实的场景不能进入发布产物。
素材缺失时保留确定性备用方案。记录声音/引擎来源、实测朗读时间、渲染配置及输出哈希，以便复现。

模块名、确切 Schema、beat 大小、有效期、修复次数和渲染 API 由原型结果决定，本文不提前固定。

## 交付顺序

| 阶段 | 交付 | 所需证据 |
| --- | --- | --- |
| 1. 叙事 | 父级绑定、有界包、不可变讲解稿 | Schema、过期输入、重放、中断和碰撞测试 |
| 2. 验证与阅读 | 独立验证者、验收回执、HTML/Markdown | 完整主张覆盖、未解决发现阻断、一致阅读视图及视觉检查 |
| 3. 场景与素材 | 场景清单、素材来源、权利回执和备用方案 | 每个场景追溯到已验证 beat 和可用素材 |
| 4. 音视频 | 授权语音、定时字幕、可复现视频 | 播放、对齐、内容、权利、身份和重试检查 |
| 5. 实跑验收 | 至少两个智能体宿主连续三期报告 | 至少一期晨报和一期晚报；固定质量、用量和时间标准 |

所有阶段均为计划中。所含阶段通过验收后，文字可以先于媒体发布。
计量及早期优化工作单独保存在[2026-08-23 实施记录](exec-plans/completed-2026-08-23-llm-usage-optimization-implementation.md)。

## 验收

保留原 G0–G7 标签，便于对照发布证据：

| 检查 | 要求 |
| --- | --- |
| G0 父级绑定 | 已完成报告及匹配索引，ID 和哈希通过检查 |
| G1 证据与新鲜度 | 关键主张在所述时间得到支持，过期证据不能作为当前有效证据 |
| G2 叙事质量 | 解释清晰、反方可信、不确定性明确，并达到版本化读者价值门槛 |
| G3 独立验证 | 完整覆盖 claim/beat，绑定确切讲解稿，无未解决关键发现 |
| G4 成本与观测 | 各阶段用量可归因，partial/unknown 明确，符合已记录预算 |
| G5 修订与恢复 | 不覆盖、安全重放、中断状态明确、并发经过测试 |
| G6 阅读投影 | HTML 和 Markdown 保持相同的已验证语义和证据链接 |
| G7 媒体准入 | 当前有效的已验证内容、授权素材和声音、技术播放检查 |

总质量分不能覆盖证据、身份、验证或权利检查的失败。发布前冻结门槛，在至少两个宿主上连续运行
三期真实报告，记录父级/讲解稿/验证修订、用量覆盖、耗时、检查结果、读者审阅和投影结果。
失败一期后，修复问题并重新开始连续验收。媒体阶段实现后单独进行真实验收。

现有报告流水线的实现缺口继续保留在[技术债追踪](exec-plans/tech-debt-tracker.md)。
