## 离线证据

以下比较的是工作次数或序列化字节，不是生产 Token 账单或端到端交付时间。测试执行耗时
也不是产品运行性能估计。

| 探针 | 优化前 | 优化后 | 解释 |
| --- | --- | --- | --- |
| 36 个不同、未缓存图片 URL，全局并发 12 | 25 批：首批 12 张，再逐张 24 批 | 3 批：12、12、12 | 下载批次/缓存检查点减少 88%，附图数与顺序保留。 |
| 同一图片运行的连接池/线程池 | 25 组 | 1 组 | 资源贯穿整轮并在结束时关闭；热缓存重跑不创建网络资源。 |
| 十个不同的 Hermes post Hook Fixture，每个报告输入 3、输出 2 Token | 110 次已验证事件文件读取 | 55 次 | 读取减少 50%；合成计量总数仍为 50。该 Fixture 是 Usage 观测，不包含 pre/error 生命周期。 |
| 300 条活跃论点和 300 条观察记录，无当期候选 | 完整 Context 约 755 KB | 投影约 45 KB | 在这个刻意放大历史的 Fixture 中，序列化字节减少约 94%；真实日报的输入规模不同。 |

历史探针每条 Claim 重复 `A bounded historical claim. ` 二十次，每条 Signal 重复
`A public signal to check. ` 二十次；每行带稳定 ID、active 状态和 geopolitics 领域。
Thesis 与 Watcher 数组各 300 行，临时路径会使字节数略有变化。当期候选继续保留，不能把
这个比例推广到每一版日报，更不能直接换算成 Token 或金额节省。

行为回归位于 `test_media.py`、`test_context.py`、`test_semantics.py`、`test_content.py`、
`test_authoring.py`、`test_workflow.py` 与 `test_llm_usage_ledger_integrity.py`。覆盖冷/热缓存、
证据迁移、状态限额、排名 29 的富化、孤立 Packet、输入替换、重复准备分析、索引提交中断、
提取/Context 失败、九个锁前竞态，以及下一次事务的账本损坏检测。最终检查全部通过：
**515 项测试**、Ruff、compileall、中文代码注释检查、文档检查及 `git diff --check`。

## 剩余边界

- 完整提取检查点形成前被杀死的进程，恢复时仍可能重做该有界抓取阶段。已过截止时间且
  没有完整检查点时，不再发起新抓取，并记录预算耗尽。遗留 Edition 锁文件仍须按运行手册
  确认原进程已退出后手动处理。
- 旧正文记录缺少摘要时仍按路径判断缓存；旧 Session 缺少逐包哈希时，不会补获历史上的
  完整性保证。新 Session 绑定当前输入，新建 Context 和 Packet 采用加强后的合同。
- 每次富化的完整检查点增加一份索引副本，哈希检查增加本地读取；这些成本用于恢复与证据一致性。
- 本次未把浏览器索引 Adapter 转成异步共享 Context API，未加入持久化报告/归档目录，也未
  完成 JSON/Markdown 配对事务。这些变化需要各自的适配器、失效与故障边界测试。
- 分阶段换模型、缩小宿主工具集、写作批次实验和审阅 Prompt 调整，仍需要宿主支持和冻结
  输入的质量对照。不能据本次离线探针宣称生产金额、总 Token、交付耗时下降或模型质量不变。
  后续问题见[技术债追踪器](tech-debt-tracker.md)。
