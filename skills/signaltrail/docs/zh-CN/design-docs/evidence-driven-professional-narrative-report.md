# 证据驱动的专业叙事日报架构

**目的：** 定义证据驱动叙事及后续媒体投影的计划中组件边界、数据流、状态所有权与持久不变量。
**状态：** 草案
**负责人：** 仓库维护者
**最后验证：** 2026-08-28

本文描述的全部组件仍处于 **Draft / Planned** 状态。本文用于指导未来实现，不代表当前运行时
行为。读者承诺见[产品规格](../product-specs/evidence-driven-professional-narrative-report.md)，
交付顺序见[活动执行计划](../exec-plans/active-evidence-driven-professional-narrative.md)。

## 决策

叙事与媒体构成 SignalTrail 权威报告的下游层。既有报告 JSON 和索引继续作为事实权威。新层
读取一份已完成 revision，创建自身不可变 revision，完成验证并发布投影，同时保持父工件不变。

确定性 Python 拥有身份、Schema 校验、证据授权、Hash、revision 分配、状态迁移、持久化和
下游准入。智能体 harness 编排有界模型工作；写作模型和验证模型只在收到的 packet 内提供
语义判断。

设计保持 harness 中立。Harness Adapter 提供执行、委派、Provider 观测和可选调度；语义契约
与验收判定保持共享。

## 依赖方向

计划中的依赖保持单向：

```text
权威报告 + 权威索引
  -> 叙事 packet 构建器
  -> 智能体 harness 写作
  -> 确定性校验器与 revision 存储
  -> 独立 claim/beat verifier
  -> 已验证闸门存储
  -> 阅读投影
  -> story stream 与授权素材
  -> TTS、字幕与新闻讲解视频
```

下游媒体可以读取已验证叙事状态。它没有写回报告、索引、连续性、来源健康或采集状态的路径。

## 组件边界

| 组件 | 计划职责 | 可信任输入 |
| --- | --- | --- |
| 权威报告读取器 | 加载一个已完成报告及匹配索引 revision | 既有校验器和持久化 Hash |
| 叙事 packet 构建器 | 选择授权证据并压缩为写作输入 | 已验证报告、索引与版本化叙事策略 |
| Harness 写作 Adapter | 分发有界叙事工作并返回候选稿 | Packet、目标语言和关联元数据 |
| 叙事校验与存储 | 校验结构和证据引用，分配不可变 revision | 候选稿、精确 packet 和父项身份 |
| 独立 verifier | 对照授权证据审阅 claim 与 beat | 已接受脚本 revision 和验证 dossier |
| 已验证闸门存储 | 把最终判定绑定到脚本与父项 Hash | 确定性结果和独立验证结果 |
| 阅读投影器 | 从一个已验证语义 revision 渲染 HTML 与 Markdown | 当前已验证闸门及其脚本 |
| Story 编译器 | 把已验证 beat 转换为有序场景 manifest | 已验证叙事与权利感知素材目录 |
| 媒体渲染器 | 生成音频、字幕、视频及技术回执 | Story manifest、授权素材与语音授权 |

精确模块名和公共 API 在实现阶段确定。上表定义的所有权边界应跨实现选择保持稳定。

## 计划工件模型

该层使用少量概念工件：

- **叙事 packet：** 提供给写作模型的有界、版本化证据输入。
- **脚本 revision：** 已接受的语义叙事，包含章节、claim 或 beat 及证据引用。
- **验证 revision：** 针对一个脚本的独立结构化判定与问题记录。
- **已验证闸门：** 绑定当前脚本、验证、报告、索引和策略版本的准入回执。
- **Story manifest：** 已验证 beat、场景与授权素材之间的有序关系。
- **媒体回执：** 音频、字幕和视频的来源、时长、权利、渲染配置与输出 Hash。

每个持久工件都携带 Schema 版本和身份。父子关系使用内容 Hash 与不可变 revision 标识。投影
可以重建，语义事实源工件保持只追加。

## 数据流

1. 父项读取器确认报告与索引已经完成、彼此一致，并符合叙事工作准入条件。
2. Packet 构建器选择父报告已经准入的精选事件、研判、综合与支持证据。
3. 活动 harness 把有界 packet 发送给写作 worker，并记录可获得的用量与耗时关联。
4. 校验器检查返回结构、证据引用、语言和父项绑定。
5. 合法候选稿获得新的不可变脚本 revision；无效工作进入可审阅的拒绝状态。
6. 隔离 verifier 使用同一授权证据生成的紧凑 dossier，审阅完整 claim 与 beat 集合。
7. 确定性代码把校验和验证结果合并为与相关 Hash 绑定的已验证闸门判定。
8. 阅读投影渲染已验证语义 revision；投影失败可以重试，且不会改变该 revision。
9. 后续阶段编译 story manifest、选择授权素材、合成获批口播、对齐字幕，并生成带独立权利和
   技术回执的视频。

## 状态所有权

| 事项 | 所有者 |
| --- | --- |
| 报告与索引身份 | 既有报告流水线 |
| 叙事 Schema 与策略版本 | 确定性核心 |
| ID、Hash、revision 与父项链接 | 确定性核心 |
| 证据允许集合与时效判定 | 确定性核心 |
| 叙事语言和分析表达 | Packet 边界内的写作模型 |
| Claim 与 beat 判断 | Dossier 边界内的独立 verifier |
| 最终准入状态 | 确定性核心 |
| Provider 执行与 worker 生命周期 | 智能体 Harness Adapter |
| 用量观测 | Harness Adapter 与不可变用量账本 |
| 场景顺序与素材权利状态 | Story 编译器与权利目录 |
| 音频时长与渲染回执 | 媒体流水线 |

模型只返回写作或评估内容。持久 ID 分配、状态推进、父工件修改和最终验证声明均由确定性核心
负责。

## 概念生命周期

叙事通常经过已计划、写作中、已校验、验证中、已验证和已投影阶段。拒绝、部分完成和过期是
带解释和父项身份的持久旁路状态。实现可以选择不同枚举名称，同时保留这些迁移语义。

已接受工件不会原地变化。修复或更新后的候选稿形成新 revision。报告、索引、证据指纹、策略
版本或相关时效判定发生变化时，旧闸门保留为历史记录，下游准入需要新的当前判定。

## 关键不变量

1. 权威报告与索引继续作为本期唯一事实权威。
2. 叙事、验证和媒体工件标识其精确父 revision 与 Hash。
3. 持久语义工件不可变并采用防碰撞写入。
4. 写作任务只接收叙事 packet 授权的证据。
5. 关键 claim 和读者可见 beat 具有可追溯验证覆盖。
6. 验证与写作保持角色隔离，verifier 不能自行晋级输入。
7. 已验证闸门是阅读和媒体发布的唯一准入记录。
8. 父项或策略变化会使依赖闸门过期，同时保留审计历史。
9. 媒体发布只使用权利状态允许且来源有记录的素材和语音。
10. 下游失败不会损害权威报告或已经验证的叙事。
11. 身份相同的已完成工作在安全条件下重用既有持久结果。
12. Harness 专属执行数据不会进入读者可见语义内容。

## 证据与时效边界

Packet 构建器从已验证父报告和索引派生证据集合。它记录报告 `as_of` 时间、证据时间戳、访问
状态，以及发现变化所需的父项指纹。写作 worker 在有界任务期间不能通过浏览或检索扩展该集合。

时效是确定性准入事项。一个策略版本定义哪些当前 claim 需要重新检查。重新检查会比较已记录
父项和证据身份与当前合格版本。基础发生变化时生成新的叙事或验证 revision；基础未变时可以
生成新的有时效闸门回执。

初版实现采用精简时效策略。具体有效期和 claim 分类将在原型与真实日报验收后确定。

## 独立验证边界

Verifier 接收已接受脚本、claim 与 beat 结构，以及从授权父内容生成的证据 dossier。它以结构化
结果报告证据支持、归因、时间适配、认知措辞、矛盾和未解决关键问题。

确定性代码确认验证覆盖精确脚本 revision 与完整预期 claim/beat 集合。所有关键问题解决后才可
获得已验证结果。编辑质量审阅独立检查连贯性、解释价值、辩证深度和读者实用性。

首轮原型将确定实用 beat 大小和修复策略。验证角色独立及其 Hash 绑定判定是持久边界。

## Harness 边界

一个 harness 集成需要：

- 在选定 workspace 和数据根中执行 SignalTrail 确定性命令；
- 把有界 packet 交给写作与验证 worker；
- 隔离写作与验证角色；
- 通过受控路径或等价结构化交接返回候选工件；
- 为可获得的用量观测保留任务关联；以及
- 明确报告中断、取消和 worker 失败。

Provider 名称、模型选择、委派工具、Hook 格式和调度器属于 Adapter。Hermes、Codex、OpenClaw
及未来 harness 可以采用不同机制，同时共享同一工件和闸门契约。真实发布验收要求跨至少两个
harness 连续完成三期日报。

## 阅读投影边界

HTML 与 Markdown 读取一个已验证语义 revision，展示证据链接、验证状态、时间语境和无障碍导航。
渲染代码转义不可信内容且不引入新 claim。两种投影即使表现形式不同，也标识同一语义 Hash。

读者反馈与已验证叙事分开保存。反馈可以通过正常 packet 与验证路径影响未来 revision。

## Story 与媒体边界

Story 编译器只从已验证 beat 创建场景。每个场景记录其叙事目的、素材身份、来源、权利状态和
备用方案。权利未知素材保持审阅状态，不能进入已发布媒体 manifest。

TTS 需要获授权语音，并记录引擎、语音、语言和输出身份。字幕时序从实际口播生成。视频渲染
消费 story manifest、音频、字幕与授权素材，同时记录足以复现和检查输出的配置与 Hash。

Story stream、TTS、字幕和视频仍是相互独立的计划阶段。阶段失败不会改变文字叙事的已验证状态。

## 失败与恢复

写入采用原子、防碰撞 revision 分配。中断工作保留最近持久状态，并可从合格边界继续。投影与
媒体渲染可从同一已验证语义输入重试；父项变化或过期时需要新的准入判定。

并发 worker 可能提交等价工作。身份与 revision 检查防止覆盖，并允许重用已接受结果。歧义或
损坏状态会停止晋级，同时保留诊断回执供审阅。

## 安全与隐私

来源内容始终作为不可信数据处理。叙事和验证 worker 只接收有界证据，不能把外部文本当作指令。
该层只保存白名单身份、计数、来源和判定；Prompt、生成 reasoning、凭据、Cookie、认证页面及
未筛选 Provider 回执不会进入持久工件。

媒体获取遵循既有公网与访问控制策略。素材权利元数据与网络安全共同构成发布条件。

这些决策需要原型、测试和真实日报证据，再进入持久架构。

## 验证策略

自动化测试覆盖 Schema 兼容、父项绑定、不可变 revision、确定性校验、verifier 覆盖、过期状态
处理、投影等价、权利准入、幂等重放和失败恢复。浏览器检查覆盖阅读体验；媒体检查覆盖播放、
字幕对齐、来源记录和权利回执。

最终晋级要求跨至少两个 harness 连续完成三期已验收真实日报，其中包含晨报和晚报。产品规格
提供发布标准，执行计划记录证据与剩余风险。

只有当实现、Schema、测试、运行和英中文档对已交付边界达成一致时，本架构才可以转为“已验证”。
