# 工程原则

**状态：** 已验证
**负责人：** 仓库维护者
**最后验证：** 2026-08-28

1. **事实源。** 版本化代码、Schema、测试和相互链接的工程记录共同说明当前行为及其
   决策依据。
2. **限定范围的入口文档。** 仓库入口概述边界，并把读者引向与任务相关的代码、测试和参考。
3. **确定性职责。** Python 管理身份、状态迁移、校验、限额和持久化；模型只在显式输入边界内
   完成选择与写作。
4. **失败状态保留。** 访问拒绝、限流和部分采集在全流程中保持独立状态与恢复信息。
5. **投影权威性。** 版本化 JSON 和 Markdown 是权威记录；HTML、PDF、桌面副本和 Notion
   是可重建的交付投影。
6. **有界语义工作。** 证据 packet、写作批次、分析 dossier 和模型用量均有明确边界，采集面
   可以独立扩展。
7. **兼容性。** 旧版来源索引结构持续可读，直至测试覆盖的迁移和发布说明定义其移除。
8. **文档验证。** CI 检查目录覆盖、中英文配对、链接完整性、验证日期和入口文档大小。
9. **生成产物。** 规范源码直接维护；发布与安装快照由对应打包流程重建。
10. **可见的技术债。** 已知差距在技术债追踪或活动执行计划中记录证据、影响和可验证退出条件。
11. **代码文档。** 维护中的定义用精简中文说明处理逻辑、输入来源、消费字段和下游输出含义；
    行内注释用于不直观的安全、状态、兼容、并发和恢复决策。

英文权威版本见 [`core-beliefs.md`](../../design-docs/core-beliefs.md)。
