## 阶段与交付物

| 阶段 | 状态 | 交付物 | 退出证据 |
| --- | --- | --- | --- |
| 0 — 契约重整 | 进行中 | 精简的双语产品与架构记录；对齐的目录和路线图措辞 | 文档检查通过，所有面向用户的引用均把能力标为 Draft / Planned |
| 1 — 叙事基础 | 计划中 | 版本化叙事 Schema、父报告/索引绑定、有界 packet、不可变脚本 revision、确定性校验 | 聚焦 fixture 覆盖合法、无效、过期、重放、中断和并发工作，且历史不被覆盖 |
| 2 — 验证与阅读 | 计划中 | 独立 claim/beat verifier、Hash 绑定已验证闸门、HTML 与 Markdown 叙事视图 | 完整验证覆盖、投影等价、浏览器 QA，以及未解决关键问题的发布阻断 |
| 3 — Story stream 与素材 | 计划中 | 有序场景 manifest、授权素材目录、来源与权利回执、确定性备用方案 | 每个已发布场景可追溯到已验证 beat 和允许使用的素材；权利未知内容保持阻断 |
| 4 — 音频与视频 | 计划中 | 授权 TTS、实测字幕时序、可复现新闻讲解视频、技术与权利 QA | 代表性日报通过播放、字幕对齐、输出身份、来源和重试检查 |
| 5 — 多 harness 验收 | 计划中 | 跨至少两个 harness 连续三期真实日报，其中包含晨报和晚报 | 每个纳入阶段都通过产品门禁、预算、重放和读者审阅，且无 harness 相关语义漂移 |

每个阶段交付可独立审阅的增量。媒体阶段失败或延期时，权威报告和已经验证的文字叙事仍然可用。

## 验证

### 自动化验证

- Schema 与持久化测试覆盖父项绑定、不可变 revision、过期依赖和防碰撞重放。
- 叙事测试覆盖证据引用、语言、确定性校验和 claim/beat 完整性。
- 验证测试覆盖角色隔离、精确脚本绑定、完整预期覆盖和明确的未解决问题。
- 投影测试比较 HTML 与 Markdown 语义身份，并检查安全浏览器渲染。
- 媒体测试覆盖场景血缘、素材权利、音频时长、字幕对齐、输出 Hash 和可恢复渲染失败。
- 文档与打包检查保持英中文记录、公开状态和已交付工件一致。

### 真实日报验证

产品晋级前，跨至少两个智能体 harness 连续运行三期日报。记录 harness、父报告与索引 revision、
叙事与验证 revision、模型用量覆盖、耗时、门禁判定、编辑审阅，以及投影或媒体结果。

连续序列至少包含一份晨报和一份晚报。某期失败或被阻断时，处理根因后重新开始连续验收序列。

### 仓库门禁

每个阶段在实现期间通过聚焦测试，并在晋级前通过完整仓库验证。阅读与媒体阶段还要在其声明
支持的环境中完成视觉或播放检查。

## 风险

| 风险 | 影响 | 计划应对 |
| --- | --- | --- |
| 叙事流畅度削弱证据边界 | 无支持的确定性或误导性因果 claim 到达读者 | 由确定性核心负责证据授权与准入，并要求独立验证和编辑审阅 |
| 写作者与 verifier 独立性不足 | 共享假设让同一错误通过两个阶段 | 隔离角色与 dossier，在验收期间比较 verifier 发现和人工审阅 |
| 验证后父证据发生变化 | 依据已经变化的解释仍显得当前有效 | 闸门绑定父项 Hash 与时效状态；父项变化后要求新判定 |
| 素材权利存在歧义 | Story 或视频无法安全分发 | 维护明确权利目录和确定性备用方案；权利未知素材保持阻断 |
| Harness 行为不同 | Provider、委派或用量差异改变结果 | 把语义门禁留在确定性核心，并要求跨多个 harness 连续验收 |
| 模型成本或耗时超过运行预算 | 叙事或媒体交付缺乏可行性 | 记录各阶段用量与耗时，应用版本化预算，并允许后续阶段继续延期 |
| 文字验证后媒体渲染失败 | 音频或视频交付不完整 | 保持媒体下游化和可重试，保留已验证文字 revision 与诊断回执 |
| 提案过早冻结实现 | 原型继承不必要字段和耦合 | 根据已测试边界和真实日报证据定稿 Schema 与 Adapter |
